## 二、修正（原文错误）

### F-1【P0】默认管理员密码描述错误

- **所在章节**：§3.2 关系型数据库、§23.3 启动命令（示例）
- **v6.0 原表述**：`init_db.py` 负责建表与种子数据（默认管理员 `admin/admin123`）；§23.3 亦写作「默认管理员：`admin / admin123`」。
- **v6.1 新表述**：初始管理员账号为 `admin`，初始密码以 `backend/README.md` 记载的实际默认值为准（并非 v6.0 所写的 `admin123`）；同时补充说明该值仅为种子默认值而非推荐配置，生产环境首次登录后必须立即修改。
- **修订依据**：`backend/README.md`（「登录账户」小节记载实际默认密码）。已全库检索确认 v6.0 所写的旧密码值仅出现于两个历史测试脚本（`backend/test_memory_e2e.py`、`backend/test_graph_data.py`），并非当前实际默认值。

### F-2【P1】PostgreSQL 下 FTS5 兜底方式描述错误（tsvector 未实现）

- **所在章节**：§3.2 关系型数据库（PostgreSQL 适配器·已知限制）
- **v6.0 原表述**：「FTS5 全文索引在 PG 端不创建，`hybrid_search` 走 ILIKE / tsvector 兜底」——暗示已有 tsvector 全文检索实现。
- **v6.1 新表述**：SQLite FTS5 虚拟表（`fragments_fts`）在 PG 端不创建，混合搜索的 BM25 通道自动降级为 **LIKE / ILIKE 关键词检索**（`_search_with_like`，无 BM25 相关性评分；PG 下使用 `ILIKE` 保持与 SQLite `LIKE` 一致的大小写不敏感语义）；`rebuild-index` 接口在非 SQLite 后端直接返回空操作提示；**tsvector 全文检索列入后续项，当前未实现**。
- **修订依据**：
  - `backend/app/services/hybrid_search_service.py`（非 SQLite 后端分支直接调用 `_search_with_like`，返回 `backend: "like"`；`rebuild_fts_index` 对非 SQLite 后端返回「当前后端无 FTS5，关键词检索走 LIKE/ILIKE」；`ILIKE`/`LIKE` 按方言选择）；
  - `backend/app/core/pg_client.py`（模块 docstring「已知限制」明确 tsvector 属后续项）。

### F-3【P1】向量重建脚本覆盖范围描述错误

- **所在章节**：§3.12 Embedding Provider 抽象、§26.2 关键约定
- **v6.0 原表述**：「切换嵌入模型后运行 `scripts/reindex_vectors.py`，将现有**记忆片段/图谱实体**重新嵌入写入新后缀集合」。
- **v6.1 新表述**：脚本从 `memory_fragments` 读取全部未删除/未过期片段批量重建，**范围仅记忆片段，不含图谱实体向量**；旧集合保持不动；按 `fragment_id` 先删后写、幂等；支持 `--dry-run` 预览；脚本实际路径为 `backend/scripts/reindex_vectors.py`。
- **修订依据**：`backend/scripts/reindex_vectors.py`（docstring 与 `load_fragments` 实现仅查询 `memory_fragments` 表，全文无图谱实体相关逻辑；`--dry-run` 参数与幂等性说明见脚本头部注释）。

### F-4【P1】Prometheus 指标数量与命名不完整

- **所在章节**：§14.4 Prometheus 指标
- **v6.0 原表述**：「17 个业务指标」，且大部分指标名省略了前缀（如 `recall_latency_seconds`、`active_count`），遗漏 W1 压缩引擎与 W4 基准/Playground 两组指标。
- **v6.1 新表述**：完整清单为 **22 个指标**，全部统一带 `agent_memory_` 前缀，以表格形式列出各指标的类型（Counter/Histogram/Gauge）与标签；新纳入 W1 组 4 项（压缩断路器状态、预算利用率、去重节省 token、压缩降级次数）与 W4 组 2 项（基准回归检出、Playground 请求计数）；并补充「未安装 `prometheus-client` 时以无操作 Stub 降级」的行为说明。
- **修订依据**：`backend/app/core/metrics.py`（逐一清点全部指标定义共 22 个，指标名、类型、标签、W1/W4 分组注释均据此转录；ImportError 分支的 `_Stub` 降级实现）。

## 三、澄清（过度声称 / 不准确表述）

### C-1【P1】向量库支持范围：Milvus / Qdrant 声称过度

- **所在章节**：§1.2 核心能力、§2.1 分层视图、§3.1 集中配置（`VECTOR_BACKEND` 行）、§3.3 向量数据库、§21.1 后端技术栈、§23.2 运行模式
- **v6.0 原表述**：多处声称「默认 ChromaDB，可切换 Milvus / Qdrant」「`chroma | milvus | qdrant`」，生产运行模式列出「Chroma/Milvus/Qdrant」。
- **v6.1 新表述**：**当前唯一生产可用的向量后端为 ChromaDB**。具体澄清：
  - `milvus_client.py` 提供独立的 Milvus 连接管理模块，但尚未接入 Store 工厂与任何业务链路；
  - Qdrant 仅有配置占位（`QDRANT_URL`），无客户端实现；
  - 将 `VECTOR_BACKEND` 配置为 `milvus` / `qdrant` 会在 Store 工厂抛出「未知的向量存储后端」错误；
  - 二者均属预留扩展点（`store/base.py` 的 `VectorStore` 抽象为其铺路）。
  上述 6 处章节均已同步改为「预留」口径。
- **修订依据**：
  - `backend/app/core/store/factory.py`（`_VECTOR_MAP` 仅注册 `"chroma"`，其余值抛 `ValueError`）；
  - `backend/app/core/milvus_client.py`（独立模块，未被业务服务引用）；
  - `backend/app/core/config.py`（仅 `QDRANT_URL` 配置项，无 Qdrant 客户端）；
  - `backend/app/core/store/base.py`、`backend/app/core/store/vector_chroma.py`（注释明确「后续切换到 Milvus / Qdrant 时只需新增实现」）。

### C-2【P1】混合搜索 BM25 对 FTS5 的依赖范围未限定

- **所在章节**：§5.2 混合搜索、§1.2 核心能力表（PostgreSQL 行）
- **v6.0 原表述**：「BM25（关键词，基于 FTS5）」，未说明 FTS5 为 SQLite 专属能力；§1.2 PostgreSQL 能力行未提及全文检索降级。
- **v6.1 新表述**：明确 BM25 基于 **SQLite FTS5**；PostgreSQL 后端无 FTS5 时自动降级为 LIKE/ILIKE 关键词检索（引至 §3.2 详述）；并补充「中文查询在 SQLite 下也有 LIKE 回退路径」；§1.2 PostgreSQL 行同步加注 FTS5 降级提示。
- **修订依据**：`backend/app/services/hybrid_search_service.py`（BM25 搜索入口的方言判断分支；`_search_with_like` 中文回退实现，注释「FTS5 中文回退方案」）。

## 四、补充（新增内容）

### A-1【P1】Embedding 切换操作指南

- **所在章节**：§3.12 Embedding Provider 抽象（新增小节内容）、§26.2 关键约定（同步引用）
- **v6.0 原表述**：仅一句「切换嵌入模型后运行 `scripts/reindex_vectors.py`」，无可执行的操作步骤。
- **v6.1 新表述**：新增完整四步操作指南（default → local BGE 示例）：① 安装 `sentence-transformers` 依赖 → ② `--dry-run` 预览待重建片段数量与目标集合 → ③ 实际重建全量向量索引 → ④ 以相同嵌入配置重启服务；并补充关键注意事项：服务运行时嵌入配置必须与重建脚本执行时一致（否则读写落在不同后缀集合导致检索为空）、回滚只需还原环境变量重启（旧集合仍在）。
